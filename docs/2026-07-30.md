## 1. 요청 배경

메일 발송과 배치잡을 위한 플랫폼 공통 기능을 만들고, 이를 관리할 수 있는 admin 웹 화면을 요청받음. 겸사겸사 최근 도입한 로그인/권한 제어 기능도 점검해서 같이 넣어달라는 요청이 포함됨.

## 2. 관리자 콘솔 구축 (PR #5)

기존 `/admin`은 사용자 관리 전용 단일 페이지였던 것을 **탭형 콘솔**로 확장: 사용자 관리 / 메일 발송 / 배치잡 / 시스템 점검.

### 메일 발송 공통 기능 (`shared/mailer.js`)
- `sendMail({ to, subject, text, html, appPrefix, sentBy })` — 모든 프로젝트/배치잡이 재사용
- 모든 발송 시도(성공/실패)를 `platform_mail_log`에 기록
- `mailLogRouter(appPrefix, { scopeToSender? })` — 프로젝트가 `router.use()`로 마운트하면 자기 앱의 발송 이력 조회 API(`GET <prefix>/api/mail-logs`)를 바로 얻음 → `projects/mdboard/index.js`에 실제로 연결

### 배치잡 공통 기능 (`core/batch.js`)
- `core/jobs/*.js`를 자동 스캔해 `node-cron`으로 등록 (프로젝트 자동 로딩과 동일한 패턴)
- 실행 이력은 `platform_batch_log`, 활성화 여부/마지막 실행 상태는 `platform_batch_jobs`에 저장
- 활성화 스위치는 "자동 스케줄"만 제어 — admin 콘솔의 "지금 실행"은 항상 동작
- 기본 잡 2개: `mail-log-cleanup`(90일 지난 메일 로그 정리), `batch-log-cleanup`(180일 지난 배치 로그 정리)

### 시스템 점검 (`GET /auth/admin/system/check`)
로그인/권한 제어(`core/auth.js`) 상태 점검: `JWT_SECRET` 기본값 여부, 활성 admin 수, 비활성 계정 수, 와일드카드(`*`) 권한 수, 앱 권한이 하나도 없는 사용자, 메일 발송 설정 여부.

**점검 중 발견해 고친 버그**: `/auth/admin/users/:id`의 PUT(비활성화)/DELETE가 **마지막 남은 활성 admin 계정**도 그냥 처리해버려서, 실수로 전 계정이 잠길 수 있었음 → 마지막 활성 admin 대상이면 차단하도록 수정.

### DB 스키마 추가
`platform_mail_log`, `platform_batch_jobs`, `platform_batch_log` (`scripts/migrate.js`).

## 3. 메일 발송 인프라 삽질기 — Railway SMTP 포트 차단 (PR #6, #7)

실제 발송을 테스트하면서 연쇄적으로 문제가 발생했고, 각각 원인을 좁혀가며 해결했다.

1. **`connect ENETUNREACH ...:587 - Local (:::0)`** — nodemailer(9.x)가 SMTP 호스트의 A/AAAA 레코드를 전부 조회한 뒤 **무작위로** 하나를 골라 접속하는데, Railway 컨테이너는 로컬 인터페이스상 IPv6가 있는 것처럼 보여도 실제 아웃바운드 IPv6 경로가 없어 간헐적으로 실패. → SMTP_HOST를 IPv4로 미리 resolve해서 리터럴 IP로 넘기는 방식으로 1차 수정 (PR #6).
2. **`535-5.7.8 Username and Password not accepted`** — Gmail이 일반 계정 비밀번호의 SMTP 로그인을 막아둔 것(앱 비밀번호 필요). 코드 문제 아님, 설정 문제.
3. **로컬은 성공, Railway는 `Connection timeout`** — Gmail 587 → 465 → Brevo SMTP 587 → Brevo 대체 포트 2525까지 전부 동일하게 타임아웃. 서로 다른 두 서비스·여러 포트에서 같은 증상이 반복된다는 건 상대 서버가 아니라 **Railway의 아웃바운드 SMTP 포트 자체가 막혀 있다**는 뜻으로 결론.
4. **최종 해결**: raw SMTP(nodemailer)를 완전히 포기하고, 이 서버가 이미 문제없이 쓰는 **HTTPS(443)로 통신하는 Brevo REST API**(`POST /v3/smtp/email`)로 전환 (PR #7). `sendMail`/`getConfigStatus`/`getLogs`/`mailLogRouter` 등 기존 공개 인터페이스는 그대로 유지해서 호출부 코드는 손대지 않았음. 새 환경변수 `BREVO_API_KEY` 필요, `SMTP_FROM`은 발신 주소로 계속 재사용, `SMTP_HOST`/`PORT`/`SECURE`/`USER`/`PASS`는 더 이상 사용하지 않음(코드에서 nodemailer 의존성 제거).
5. **결과**: Railway 배포 후 관리자 콘솔에서 테스트 메일 발송 성공 확인.
