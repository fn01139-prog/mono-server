# 개발 세션 노트 — 2026-07-17

> 브랜치: `main`
> 배포: Railway (`https://fn0113.up.railway.app`)
> 주제: 메인 허브 로그인 + 앱별 데이터 격리 (통합 인증 시스템) 설계 및 전체 구현

---

## 1. 요청 배경

메인 허브에 로그인 기능을 추가해 권한이 있는 앱만 사용할 수 있게 하고, 각 앱 내부에서도 기본적으로 본인 데이터만 조회할 수 있도록 해달라는 요청. 먼저 설계 문서만 작성한 뒤, 승인 후 실제 개발까지 같은 세션에서 이어서 진행했다.

## 2. 설계 문서 작성 (`docs/auth-design.md`)

기존 상태를 조사한 결과, 앱마다 인증 방식이 제각각이었다:

| 앱 | 기존 인증 | 문제 |
|---|---|---|
| campchecklist | JWT + bcrypt (완전한 계정 시스템) | 유일하게 제대로 된 인증 |
| mdboard / portfolio | 단일 비밀번호 HMAC 토큰 | 계정 개념 없음 |
| floorplan | 원시 관리자 토큰 | 계정 개념 없음 |
| travellog / mindmap | 없음 | 전체 공개 |

설계 방향을 정하고 5개 결정 필요 사항(portfolio 공개 조회 방식, floorplan 권한 범위, mdboard 격리 방식, campchecklist 컨셉, 토큰 만료)에 대해 사용자 답변을 받아 문서를 확정했다. 핵심 결정:

- **campchecklist 초대 모델**: 참여자가 스스로 참여/탈퇴하는 방식 → 생성자가 참여자를 추가하는 방식으로 컨셉 변경
- **mdboard 파일 권한**: 파일 자체는 격리하지 않고, 파일별 소유자/공유 권한을 DB로 관리
- **floorplan**: 조회는 로그인 사용자 전원, 수정은 본인 것만
- **portfolio**: URL 기반 공개 페이지(`is_public`/`published`) + 앱 권한 와일드카드(`*`) 둘 다 지원
- **DB/명칭 통일**: mindmap의 독립 DB pool과 비표준 테이블명을 플랫폼 공통(`shared/db.js`)으로 승격

## 3. 전체 구현 (11단계)

설계 승인 후 `Phase 1~5` 순서로 실제 개발까지 같은 세션에서 진행했다.

### Phase 1 — 플랫폼 인증 기반
- `platform_users` / `platform_accounts` / `platform_app_grants` 테이블 (`scripts/migrate.js`)
- `scripts/migrate-auth.js` — admin 계정 자동 부트스트랩, 레거시 `camp_users`/`camp_accounts` 데이터를 `platform_*`로 이관, `camp_trips.owner_id` 백필, mdboard 레거시 파일 등록 (멱등, 서버 기동 시 자동 실행)
- `core/auth.js` — JWT + httpOnly 쿠키 발급/검증, `attachUser`/`requireLogin`/`requireApp`/`requireRole` 미들웨어
- `core/auth-routes.js` — `/auth/login`, `/auth/logout`, `/auth/me`, `/auth/admin/*`(사용자·권한 관리 API)
- `core/views/login.html` — 로그인 페이지
- `app.js` — 허브(`/`)에 로그인 요구 + 권한 있는 앱만 카드로 노출

### Phase 2 — 앱 접근 제어
- `core/loader.js` — 앱을 마운트할 때 로그인/권한 가드를 정적 파일·API·customRoutes·SPA catch-all 앞에 자동 삽입
- `config.publicPaths`(API용) / `config.publicStaticPaths`(정적·SPA용) 분리 지원 — 같은 이름의 경로라도 마운트 위치에 따라 의미가 다르기 때문
- `shared/public/auth-guard.js` — 모든 앱 공통, API가 401을 반환하면 `/login`으로 리다이렉트하는 fetch 래퍼

### Phase 3 — 데이터 격리
- **mindmap**: 자체 DB pool(`db/pool.js`) 제거하고 `shared/db.js`로 통합, `mindmap_board` 등 구 테이블명을 `mindmap_boards` 등으로 표준화(RENAME), `owner_id` 기준 격리
- **travellog**: `travel_trips.owner_id` 기준 격리, 하위 일정/기록/사진은 trip 소유권 경유 검사
- **portfolio**: `owner_id` 격리 + `status='published'` 페이지는 비로그인 공개 조회, HMAC 인증(`/studio` 비밀번호 모달) 완전 제거
- **floorplan**: 조회는 전체 허용(소유자 표시), 수정/삭제는 소유자만, 관리자 토큰 로그인 UI 제거하고 `canEdit` 플래그 기반으로 프론트 전환

### Phase 4 — 컨셉 변경
- **campchecklist**: 자체 회원가입/로그인 라우트 제거하고 플랫폼 로그인 사용, self-join(`/trips/:id/join`) 제거 → 생성자가 참여자를 추가하는 `PUT /trips/:id/participants`로 교체, `GET /members`(앱 권한 보유자 목록) 신설
- **mdboard**: `mdboard_files`/`mdboard_file_grants` 테이블로 파일별 소유·공유(read/write, `*` 전체공개) 권한 관리, `permissions.js` 모듈 신설, 파일 목록 조회 시 미등록 파일 자동 등록(self-healing), 공유 UI 추가

### Phase 5 — 관리 화면
- `/admin` 페이지 (`core/views/admin.html`) — 사용자 생성, 앱 권한 편집(와일드카드 포함), 비밀번호 초기화, 활성화/비활성화, 삭제

## 4. 검증

실행 중인 서버(로컬, Railway PostgreSQL 연결)에 대해 실제 브라우저와 curl로 종단간 테스트 28건 전부 통과. 상세 결과는 `docs/auth-test-results.md` 참고.

### 검증 중 발견해 수정한 버그 4건

1. **로그아웃 쿠키 미삭제** — `clearCookie()`에 옵션이 없어 로그인 시와 속성이 달라 브라우저가 삭제로 인식하지 못함
2. **floorplan 이름 재사용 취약점** — 같은 이름으로 저장 시 소유권 검사 없이 타인 데이터를 덮어쓸 수 있었음
3. **publicPaths 마운트 충돌** — API/정적 마운트가 같은 공개 경로 목록을 공유해 `GET /pages`(로그인 필요한 목록)가 실수로 공개됐던 문제 → `publicPaths`/`publicStaticPaths` 분리로 해결
4. **`req.path` 마운트 깊이 문제** — Express가 중첩 라우터 안에서 `req.path`를 상대경로로 잘라내는 것을 놓쳐 `/auth/me`가 401 대신 302로 응답하던 문제(겉보기엔 fetch가 리다이렉트를 따라가 정상처럼 보임) → `req.originalUrl` 기준으로 수정

## 5. 의도적으로 보류한 사항

- `camp_users`/`camp_accounts` 테이블은 설계상 삭제 대상이었으나, 라이브 프로덕션 DB에 대한 `DROP TABLE`은 되돌리기 어려워 이번엔 보류. 데이터는 `platform_*`로 전부 이관되었고 코드에서도 더 이상 참조하지 않음(FK도 재지정 완료) — 운영 확인 후 별도 정리 권장.
