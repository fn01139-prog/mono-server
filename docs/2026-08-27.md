# 개발 세션 노트 — 2026-08-27

> 브랜치: `claude/mdboard-content-migration-uxkfjy` → `main`
> 배포: Railway
> PR: [#43](https://github.com/fn01139-prog/mono-server/pull/43) (머지 완료)

mdboard 콘텐츠 저장 방식을 "매 요청마다 Google Drive와 실시간 동기화"에서
"Railway 볼륨에 상시 저장 + Drive는 월 1회 백업"으로 바꿨다. 기존엔 Railway
컨테이너 디스크가 재배포마다 초기화되는 걸 Drive 동기화로 우회하던 구조였는데,
이제 볼륨 자체가 영속 저장소가 되면서 그 우회가 필요 없어졌다.

---

## 1. 저장 경로 변경

- `projects/mdboard/paths.js` 신규 — `CONTENTS_DIR` 단일 정의 (`index.js`, Drive
  스크립트, 배치잡 공용)
  - 기본값: `/data/contents/mdboard` (Railway 볼륨 마운트 경로)
  - `MDBOARD_CONTENTS_DIR` 환경변수로 오버라이드 가능 (로컬 개발용)
  - 모듈 로드 시점에 디렉토리를 미리 생성 — `config.js`가 정적 마운트 등록 전에
    이 모듈을 먼저 require하므로, 존재 여부로 마운트를 결정하는 `loader.js`보다
    항상 먼저 실행되도록 순서를 맞췄다
  - 생성 실패 시(볼륨 미마운트 등) 원인을 짚어주는 에러 메시지와 함께 기동 중단

- `core/loader.js`에 `config.staticMounts` 옵션 추가
  - 기존엔 프로젝트별 정적 파일이 항상 `projects/<name>/public/` 밑에서만
    서빙됐는데, mdboard 콘텐츠(이미지, 업로드된 HTML)는 이제 그 바깥(볼륨)에
    있어서 별도 정적 마운트가 필요했음
  - `projects/mdboard/config.js`에서 `/mdboard/contents` → 볼륨 경로로 매핑,
    `public/` 마운트보다 먼저 등록해 우선권을 줌
  - 로그인 가드는 기존 `public/` 마운트와 동일하게 적용됨

## 2. Google Drive 연동 정리

기존 `projects/mdboard/drive.js`(요청마다 push/pull하던 실시간 동기화)를 삭제하고
용도별로 분리했다.

- `projects/mdboard/driveClient.js` — 저수준 Drive 클라이언트(목록 조회/다운로드/
  업로드-갱신). 마이그레이션 스크립트와 백업잡만 사용, `index.js`는 더 이상
  Drive를 몰라도 됨
- `scripts/mdboard-drive-migrate.js` — 레거시 Drive 백업분 → 볼륨 1회 이관
  (Drive 파일명의 `/`로 인코딩된 폴더 구조를 그대로 디코딩)
- `core/jobs/mdboard-drive-backup.js` — 볼륨 → Drive 월 1회 백업 배치잡
  (`0 3 1 * *`, 매월 1일 03:00), md/html/이미지 전부 대상, 삭제는 반영 안 함
  (누적 백업이라 안전)

## 3. 환경변수

| 변수 | 기본값 | 용도 |
|---|---|---|
| `MDBOARD_CONTENTS_DIR` | `/data/contents/mdboard` | mdboard 콘텐츠 저장 경로. 로컬 개발은 `.env.example`에 프로젝트 내 상대경로로 오버라이드 예시 포함 |
| `MDBOARD_FOLDER_ID` | (없음) | mdboard 전용 Drive 백업 폴더 ID — 마이그레이션 스크립트/백업잡이 사용 (기존 `GDRIVE_CLIENT_ID/SECRET/REFRESH_TOKEN`은 그대로 재사용) |
